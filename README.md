# 自动续火花（AotuFire）

每天定时自动打开多闪，给名单里的每位好友各发一条消息，让聊天火花不断。

- **纯本地运行**：不申请联网权限，不上传任何数据
- **无需 root**
- **零第三方依赖**：只用 Android SDK 原生 API

> 本工具针对**多闪**（包名 `my.maya.android`）适配，不适用于微信、QQ 等其他应用。

**分享给别人时，请用正式签名版 `app-release.apk`，并附上 `安全验证说明.md`。**
该文档列出了 APK 的 SHA-256 与签名证书指纹，接收方可以自己动手核对，
而不必凭感觉相信。调试版（`app-debug.apk`）**不要外发** —— 它用的是公开的调试密钥，
任何人都能签出同名的伪造包，无法证明来源。

## 一、功能

| 功能 | 说明 |
|---|---|
| 每天自动执行 | 到点自动亮屏 → 输密码解锁 → 打开多闪 → 逐位发送 |
| 多位好友 | 昵称一行一个，自动逐个处理 |
| 随机文案 | 文案池里每次随机抽一条，避免每天一模一样 |
| 结果通知 | 成功/失败都会发通知，失败会提示你手动补 |
| 一键执行 | 界面上的「立即执行一次」可随时手动跑，不用等定时 |
| 诊断包 | 出问题时一键导出完整日志和界面快照 |

**执行流程**

```
设定时间到
  → 自动点亮屏幕
  → 自动输入密码解锁
  → 打开多闪，回到消息列表
  → 好友 1：定位会话 → 核对是本人 → 发消息 → 确认已送达
  → 随机等几秒
  → 好友 2：……（同上，直到全部处理完）
  → 回到桌面并锁屏
```

## 二、运行环境

| 项目 | 要求 |
|---|---|
| 手机系统 | Android 11 及以上（API 30+） |
| 适配重点 | Android 14～16；小米 / 澎湃 OS 有专门适配 |
| 其他 ROM | 华为、OPPO、vivo、三星均可运行，保活设置项名称不同 |
| 资源占用 | 极低，无后台常驻进程（到点由系统闹钟拉起） |
| 网络 | **完全不需要联网** |

**手机的 8 项权限**（界面「环境自检」里逐项引导，缺一不可）：

| 权限 | 作用 | 缺失后果 |
|---|---|---|
| 无障碍服务 | 读取界面、点击、输入 | 完全无法工作 |
| 悬浮窗 | 任务期间保持屏幕常亮 | 屏幕自动熄灭，流程中途断掉 |
| 通知 | 展示执行结果 | 看不到成功还是失败 |
| 全屏通知 | 到点由系统点亮屏幕并唤起解锁 | 唤不起解锁面板 |
| 精确闹钟 | 到点准时执行 | 时间可能被推迟几十分钟 |
| 忽略电池优化 | 避免凌晨被系统冻结 | 凌晨被系统掐掉 |
| 前台服务 | 任务执行期间防冻结 | 跑到一半被系统挂起 |
| 开机自启 | 重启后恢复定时 | 重启一次，定时永久失效 |

> 此外需要「按包名启动应用」的包可见性声明，用于拉起多闪（安装即生效，无需手动设置）。

## 三、安装与配置

### 1. 安装

把 `app-debug.apk` 传到手机（微信/QQ 文件传输助手或数据线），点击安装。
需要允许「安装未知来源应用」。**覆盖安装即可，不用卸载旧版。**

### 2. 开启权限

打开 App，界面顶部是橙色卡片，下面第二张是「环境自检」。**逐项点成绿色**：
每一行右侧都有「设置」按钮，点一下直接跳到对应系统页面，允许即可。

### 3. 小米 / 澎湃 OS 额外三步

点自检卡片底部的「小米专属」按钮会弹出说明，也可以按路径手动设置：

```
设置 → 应用设置 → 应用管理 → 自动续火花 → 权限管理 → 其他权限
  → 「后台弹出界面」→ 允许
同页顺带设置：自启动 → 打开；省电策略 → 无限制
```

> 小米的「后台弹出界面」是独有权限，不做这三步会出现「到点只亮屏、不干活」。

### 4. 填写设置

| 项目 | 说明 |
|---|---|
| 每天触发时间 | 建议 `01:00`。此时你不会用手机，也不会打扰到好友 |
| 要续火花的好友 | **一行一个昵称**，必须与多闪里显示的**完全一致** |
| 锁屏密码 | 6 位数字，仅保存在本机，用于自动解锁 |
| 文案池 | 一行一条，每次随机抽一条发出 |

填好后点「保存并排定闹钟」，会提示「下次触发：xx-xx xx:xx」。

## 四、注意事项

### ⚠️ 必须遵守

**1. 好友昵称必须填写，且要完全一致**

这是本工具**防止发错人**的第一道闸门。昵称对不上的那一位会被**跳过**，
而不是随便找个人顶上。如果某天某位好友没收到，
**宁可去看一眼通知，也不要去掉昵称省事**。

**2. 不要用系统里的「强制停止」**

- 「最近任务里清空后台」→ 没问题，闹钟还在，到点照常执行
- 「应用信息页 → 强制停止」→ **会取消所有闹钟**，必须手动打开一次 App 才能恢复

**3. 不要把省电策略设成「智能限制」或「优化」**

必须设为「无限制」并加入电池优化白名单，否则凌晨的定时可能被系统延迟甚至取消。

### 建议做法

**4. 保持手机插电**

凌晨执行时手机通常处于深度休眠，插电可以避免电量过低被系统限流。

**5. 首次先填 2～3 位好友试跑**

确认每位昵称都能对上、都能成功发送，再扩展到更多。
每位好友之间有 6～14 秒的随机间隔，10 位大约需要 2～3 分钟。

**6. 凌晨执行窗口前后不要清后台**

任务执行期间（约 1～3 分钟）如果清空后台，任务会被打断，
可能出现「前几位发了、后几位没发」的半截状态。

**7. 可以在最近任务里「下拉锁定」本应用**

小米/澎湃 OS 的锁图标能保护它在一键清理时被跳过，更省心。

### 需要了解

**8. 锁屏密码以明文保存在本机**

保存在应用私有目录，程序不联网、不会离开手机。但确实是明文存储，卸载 App 即一并删除。

**9. 执行失败当天不会自动重试**

会发通知提醒你手动补一条。当天没有被闹钟成功拉起（例如手机处于关机状态）也不会补跑。

**10. 频率不建议提高**

程序每天只跑一次、走正常的前台界面点击（不是协议接口）、文案随机、好友之间有随机间隔。
这是为了降低被平台判定为机器操作的风险，**不建议再加大频率**。

## 六、常见问题

**Q：早上没收到通知？**
先看开关是否开着、通知权限是否为绿色；再看电池优化是否已忽略。

**Q：到点只亮屏，没有后续动作？**
检查「全屏通知」和「悬浮窗」是否为绿色；小米用户再检查「后台弹出界面」。

**Q：某位好友被跳过？**
昵称和多闪里显示的不一致。打开多闪对照一下，改掉即可。

**Q：密码安全吗？**
存在应用私有的本机目录里，程序不联网，不会离开手机；但确实是明文。

**Q：换手机了怎么办？**
按第二章的配置步骤重新做一遍。非小米机型跳过第 3 步，
但要在各自的「应用管理」里打开自启动和后台运行权限。

**Q：能续微信 / QQ 吗？**
不能。本工具的界面定位是**按多闪实测适配**的，换应用需要重新采集界面结构。

**Q：为什么要有 6～14 秒的间隔？**
短时间连发是机器人最明显的特征，随机间隔既像真人操作，也避免点击过密被系统吞掉。

```powershell
$env:JAVA_HOME='<Android Studio 自带的 jbr 目录>'
cd <项目目录>
.\gradlew.bat assembleDebug
```

**核心模块**

| 模块 | 职责 |
|---|---|
| `MainActivity` | 主界面：自检、配置、手动执行、诊断 |
| `FireScheduler` / `FireAlarmReceiver` | 每日闹钟的排定与触发 |
| `FireService` | 前台服务，任务期间防止进程被冻结 |
| `TaskRunner` | 执行链状态机：唤醒 → 解锁 → 逐位发送 → 收尾 |
| `WakeActivity` / `WakeTest` | 亮屏与解锁面板（含备用解锁通道） |
| `DuoshanDriver` | 多闪界面定位与操作 |
| `FireAccessibilityService` / `NodeDump` | 无障碍能力与界面结构导出 |
| `ScreenKeeper` | 任务期间保持屏幕常亮 |
| `Notifier` | 通知、全屏意图、结果推送 |
| `Exporter` / `ExportProvider` | 诊断包的导出与分享 |

> 界面结构的实测数据与各模块的实现细节，整理在 `开发记录.md` 里，继续改代码前建议先看那份。
